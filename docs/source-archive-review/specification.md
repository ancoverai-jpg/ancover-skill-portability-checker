# Ancover Source Archive Review — specification, 2026-11-04
Narrow existing release-evidence candidate to an artifact review task rather than another documentation runner. Audience: maintainer distributing small source ZIPs to users without Git checkout. Consequence: release source archives can omit build prerequisites even when download/extraction succeeds.
Demand: three authors in three communities, dated public reports: https://github.com/openthread/ot-br-posix/issues/3496 (BKPepe, 2026-08-04T05:19:05Z, closed); https://github.com/Goddard-Fortran-Ecosystem/pFUnit/issues/101 (ZedThree, 2019-04-09T14:32:23Z, open); https://github.com/AcademySoftwareFoundation/MaterialX/issues/317 (nzanepro, 2019-11-22T03:21:14Z, closed). Two cases are closed; one is historical/open. Do not claim these projects remain broken. Natmap6 has the same author as ot-br3496 and is excluded from the independent count. UniRig66 does not establish an archive problem in its opening report and is excluded.
Alternatives: GitHub official LFS archive setting controls pointer vs content and can incur repository bandwidth; do not change it or download LFS objects automatically. Kentzo/git-archive-all generates archives with submodules; prefer existing packagers. Git LFS pointer/fsck tools require the relevant Git/LFS environment and inspect repository objects, not this selected ZIP profile.

Proposed gap: an offline, non-extracting review of the actual ZIP plus explicit expected files/nonempty prefixes, with canonical small LFS pointer detection and bounded metadata review. Not a packager, signature checker, complete LFS validator or build verifier. Confidence medium on need; low-to-medium on product gap. Editorial scores1-5 favorable: pain4 evidence3 gap2 demonstrable-value4 adoption3 Skill-fit4 enterprise-use3 maintenance4 Ancover-fit4. One small Skill grouped into existing portability/release-tools repository.
Architecture: Python3.10+ standard library helper; no server, dependencies, subprocess, network, archive extraction, LFS hydration or repository mutations. Reads two explicit regular files. Manifest max1MiB, ZIP max16MiB, <=10000 members, <=256MiB declared uncompressed total. ZIP entries <=1024 bytes are read for strict3-line LFS pointers; larger entries are not inspected for content/CRC. Stored/deflated ZIP only. This is not a hostile-filesystem security sandbox.
Contract: schemaVersion1, sourceRevision40lowercasehex (operator assertion), rootPrefix empty or safe relative directory ending slash, requiredFiles array of exact relative files, requiredPrefixes array of relative directory prefixes ending slash; combined1-100 entries, duplicates invalid. Names reject controls, backslash, absolute/traversal/dot components and drive prefixes. UTF8 JSON duplicate fields and unknown fields rejected. No implicit root stripping.
Output: JSON with archive SHA256, declared revision, flags, missing files and empty required prefixes. Explicitly supplied policy and metadata evidence, no file contents, pointer OIDs, credentials or input paths. Names remain visible. Exit0 configured checks found no findings; exit1 findings; exit2 malformed/unsupported input. No inference of a successful build, fully bundled submodule tree, authenticity, absence of secrets or safe extraction.
Acceptance: valid archive control; missing exact file; empty/partial required prefix; canonical pointer; deliberate pointer fixture reported for review rather than claimed exploit; path traversal, duplicate names, case collision, symlink metadata; invalid ZIP/JSON/UTF8/schema; compressed-size and member limits; fixed diagnostics; real CLI invocation; input bytes unchanged/no extraction. Isolated Codex install/reinstall/removal and installed helper execution. Claude Code and host triggers explicit NOT_TESTED when unavailable. Actual ZIP of own published v0.2.0 inspected under predeclared expectations. Exact source review and CI on remote commit before publication.
Predeclared evaluation: baseline only confirms ZIP opens. Seed missing required source, an empty required submodule prefix and canonical LFS pointer, plus valid control. Measure bounded fixture detection only, not general security or agent quality.
Demo: synthetic incomplete source ZIP; real published own source ZIP. Maintenance: watch Python ZIP and Git LFS specs; preserve limits and no auto-extraction. Future TAR support only after separate evidence/testing.
