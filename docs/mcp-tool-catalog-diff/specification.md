# MCP Tool Catalog Diff — specification
Experimental selected-data comparison, not MCP protocol validation, trust pinning or security classification.

Workflow: obtain two separately authorized complete tools/list-style captures from the same intended server/context; preserve source/revision/time and protocol in private acquisition evidence; explicitly build profile snapshots; run a trusted installed helper; review changed indices privately; perform actual client integration checks separately. Never execute descriptions or invoke a target tool solely because it is present.

Input profile ancover-mcp-tool-catalog-v1: two UTF-8 JSON regular files <=1MiB each, root profile/serverKey/complete:true/tools; no nextCursor field; <=256 unique case-sensitive nonempty tool names,<=256 characters each; each declaration requires an object inputSchema. serverKey is an exact matching nonempty operator assertion <=128 characters, not authenticated identity. Root acquisition metadata is not part of tool equality. Complete flag does not prove all pages were acquired.
Strict JSON duplicate-key/non-JSON-constant rejection,<=12000 value nodes, depth<=48, numeric lexemes<=128 characters. Numbers retained as exact tokens, so1,1.0,1e0 differ; no floating-point rounding. Object keys sorted recursively; tool list reordered by identity; arrays and string whitespace unchanged. Unknown declaration fields compared as other. Omitted/null differ. This typed internal representation is neither RFC8785/JCS nor semantic JSON Schema equivalence.

Outputs: UNCHANGED/0, REVIEW_REQUIRED/1, INDETERMINATE/2. Added/removed/modified counts and tool-name SHA256 plus before/after array indices; fixed field categories only, no raw names/values/schema/paths. Raw snapshot SHA256 binds selected files. Same name with changed description/input/output/annotations/unknown fields must require review. Rename is removal+addition, never inferred compatible. Hashes and indices are sensitive if linked with known inputs.

Permissions: read only the two selected files; no network, server process, external refs, target tool calls, dependency fetch, file mutation or approval changes during checking. Use stable local files; not a sandbox against concurrent filesystem races/resource contention. Python3.12+ stdlib, no new package dependency. Existing package CI installs dependencies for older helpers separately.
Acceptance: meaningful same-name changes, reorder-only equality, unknown fields, missing-vs-null, numeric precision/spelling, duplicate keys/names, wrong scope/partial pagination/malformed/oversize/deep/count-limited input, actual CLI/read preservation and value suppression; isolated host installation/update/removal, EN/PT-BR docs, license/CI/exact remote file review. Codex conversation and Claude unavailable coverage NOT_TESTED, experimental. No unperformed transport/integration/security claims.
