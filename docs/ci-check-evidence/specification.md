# Ancover CI Check Evidence — candidate specification
Audience: maintainer reviewing CI evidence before a release. Task: compare an explicit expected-check policy with a bounded, operator-selected snapshot for one exact revision. Consequence: missing checks, unexpected skips, cancelled runs and ambiguous contexts must remain visible rather than becoming a vacuous green.
Demand: three independent authors, three project/forum communities. These are public reports, not independently reproduced upstream defects.
- gustaff-weldon, 2022-06-13, actions/runner discussion 1943, unanswered: path-filtered required workflows and ambiguous dummy contexts.
- whois-jon-peterson, 2020-05-18, community discussion 26945, answered: skipped dependency and job-level conditions. Historical workaround, not a claim of a current unfixed defect.
- crrow, 2026-07-04, rararulab/rara issue 2179, closed: skipped callers fail to create required reusable-workflow contexts. Closed and treated as historical.

Alternatives:

Proposed narrow gap: deterministic, names-and-results-only evaluation of explicit expected context plus app identity, with no universal acceptance of skipped and no pass for empty or incomplete snapshots. Confidence medium on task need, low-to-medium on differentiation. No adoption or enterprise-sales claim.
Editorial scores (1-5, higher favorable): pain4 evidence3 gap2 demonstrable-value4 adoption3 Skill-fit4 enterprise-use4 maintenance4 Ancover-fit4. Small scope and no network are maintainable; manual policy configuration limits adoption.
Architecture: one Skill, Node22+ standard-library-only evaluator, JSON fixture. Group with existing portability/release tools rather than create another repository. No server, dependency, token handling, network, command execution, ruleset changes or automatic merge. Read explicitly selected JSON file only; regular file, UTF8, max1MiB, max100 expected/observed rows. Errors use fixed categories without raw data. Output approved check names, app IDs and categorical outcomes, never logs.
Contract: schemaVersion1, expectedSha40hex, observedSha40hex, complete boolean, expected[{name,appId,allowSkipped:boolean}], checks[{name,appId,status,conclusion}]. Strict fields. Check status queued|in_progress|completed; recognized conclusions only. Duplicate expected identity invalid; duplicate observed identity AMBIGUOUS. Optional contexts outside policy are ignored and counted, not represented as having been tested. All expected contexts must be present with one matching app ID; app mismatch is MISSING. Skipped is recorded as POLICY_ALLOWED_SKIP only when explicitly allowed; it never becomes proof of test execution.
Outputs: report evidence OPERATOR_SUPPLIED_SNAPSHOT, policySatisfied boolean, counts, per-policy outcomes. Exit0 policy satisfied,1 gaps/mismatch/incomplete,2 invalid input. Global SHA mismatch/incomplete snapshot makes policy unsatisfied regardless of row status. Empty policy invalid; empty checks must fail.
Workflow: identify requested revision and expected policy from maintainer configuration; collect all API pages with their revision; retain complete:false when pagination cannot be checked; normalize only the selected attempt without combining multiple revisions/apps; run offline evaluator; compare its result to the actual CI details and preserve uncertain evidence. Report does not authenticate a snapshot or read branch protection.
Acceptance before publication: meaningful tests for positive, missing, failure, cancellation, unexpected skip, allowed skip, empty policy, empty checks, incomplete, SHA mismatch, app mismatch, duplicate identity, strict types, hostile names, oversize, invalidUTF8, fixed diagnostics and no file writes. Real CLI invocation plus isolated install/update/uninstall and configuration preservation. Explicit and implicit conversational triggering and Claude runtime are separately NOT_TESTED if unavailable. CI on exact remote commit and file review needed before publication.
Predeclared baseline: every observed completed row has success or skipped. Seed one absent expected context, one unexpected skip, one SHA mismatch, plus a valid control. Baseline should miss those three; treatment must flag all three and accept control. This is a synthetic fixture comparison, not measured agent improvement or a competitor benchmark.
Demo: run a synthetic same-SHA snapshot with expected build+integration but only build success; report MISSING integration and exit1. Maintenance: watch official check conclusion semantics; no automatic policy broadening. Runtime without Node is NOT_TESTED; no model/API calls.
Publication status: NOT_PUBLISHED. Demand alone does not satisfy the validation and publication gates.
